● Yes, this works on Netlify. Built and verified against the live API.

  How it works

  Cumulative totals can't come from GitHub — the traffic API only returns a
  rolling 14-day window, so anything older is gone permanently. The tracking has
  to be ours:

  - netlify/functions/lib/traffic.mjs — stores traffic keyed by day per repo
    (repo:<name> → { days: { "2026-09-10": { clones, views, … } } }). Cumulative
    = sum of every day ever stored. Because days are keys rather than a running
    counter, re-snapshotting rewrites the same days instead of adding to a
    total, so snapshots are idempotent — run it ten times an hour, the number
    doesn't inflate. A day already on record is raised to the higher count,
    never lowered, since today's count is still climbing when first seen.
  - netlify/functions/traffic-snapshot.mjs — a scheduled function (export const 
    config = { schedule: '@daily' }) that snapshots every repo. This is the part
    that makes it cumulative: it captures each day well inside GitHub's 14-day
    window.
  - netlify/functions/github-traffic.mjs — reads the cumulative store. If the
    last snapshot is older than 6h (or the store is empty, e.g. first deploy),
    it collects inline first, so it bootstraps itself without waiting for the
    cron.
  - Persistence is Netlify Blobs (@netlify/blobs, added to package.json) —
    functions are stateless with no writable disk, and Blobs survives deploys.
    No external DB needed.

  Verified locally with a filesystem stand-in for Blobs, hitting the real GitHub
  API:

  after snapshot 1: clones=189 views=262 repos=12 since=2026-08-27
  after snapshot 2: clones=189 views=262 repos=12 since=2026-08-27
  idempotent: YES          sum check: repo clones sum == total

  Nice bonus: the very first snapshot seeds 14 days of history for free (back to
  2026-08-27), because that's the window GitHub hands over. From there it only
  grows.

  One bug I found and fixed while in there: the old function used export default
  (Netlify Functions v2) but returned { statusCode, body }, which is the v1

  Response shape is now { configured, clones, views, uniques, repos: [{ name,

  A. The stamp block

  Adinkra isn't an icon set — it's a printing process. Carved calabash stamps,
  dipped in adinkra aduru ink, pressed in a grid onto cloth, the grid ruled off
  by combed lines (that comb pattern is itself a symbol, nkyimu).

  generic default; hand-stamped cloth is never perfectly aligned, and that
  misalignment is what makes it read as craft rather than CSS.

  Adinkrahene — concentric rings, "greatness, leadership," said to be the chief

  single continuous gold stroke that writes itself on load over about two
